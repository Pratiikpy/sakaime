# Requirement-to-implementation-to-test-to-evidence matrix

## Results as of 2026-10-27

The measured results behind this matrix are in [`../evals/RESULTS.md`](../evals/RESULTS.md) (generated from `evals/results/`), with the contamination log in [`../evals/ERRATA.md`](../evals/ERRATA.md). The Zetaris gate record is [`../infra/zetaris/GATES.md`](../infra/zetaris/GATES.md). Every status below was set on 2026-10-27 from a file that exists in the repository or from a command run that day (named in the row). Where a row could not be verified from files it says so.

**How to read the status column.** The four states are PASS, FAIL, PENDING and BLOCKED. PASS needs a named evidence file and a read of the source of truth. BLOCKED needs three serious attempts written down; nothing here is BLOCKED except the Zetaris natural-language route, whose three attempts are in `infra/zetaris/GATES.md`. A row whose parts are in different states shows the **worst** state (FAIL, then BLOCKED, then PENDING, then PASS), and the evidence column gives the state of each part. "Partial" in the evidence text means some of the row's own pass condition holds and some does not.

**Checks run on 2026-10-27 for this matrix.**

- `npm run judge`: 67 lines PASS, 0 FAIL, 5.5 s, no key, no network (the working tree, not a fresh clone).
- `npx vitest run`: 133 test files passed and 3 skipped; 3,140 tests passed and 23 skipped (the skips are live-service tests that need a key or the Zetaris stack and say so).
- `gh repo view`: the repository `Pratiikpy/sakaime` is public, and its default branch holds one commit (the design documents); the 31 later local commits are not pushed.
- Browser tests (`npx playwright test -c tests/ui/playwright.config.ts`, 73 tests, real Chrome against the fixture server with the real compiler): 67 passed, 2 skipped, and 4 errored at context close with a file-not-found error inside `tests/ui/.results`, because the output folder was shared with another process (a harness collision, not a product result). Those four tests (axe light desktop, axe on a phone, the mobile screenshot run and the empty-federation state) were rerun alone with a separate output folder and passed (8 of 8 tests selected by those line numbers). The screenshots they wrote were not read by the author of this matrix, so a visual review of them is not recorded here.

Every result is tagged by what it supports: **[T1]** Track 1 capability, **[REL]** scientific reliability, **[DEM]** demand. Passing one never counts as passing another. Source precedence: the live HackOS page, Official Rules and written organizer decisions; then the supplied guides; then verified sponsor contracts; then our design. Organizer wording is in the sibling project's notes (not in this repository, read-only).

**What the results say, in four sentences.** The compiler never labelled an unsupported claim as supported in any set (0 of 198 controlled, 0 of 17 development, 0 of 15 held-out). The full pipeline is conservative to the point of cost: on the 26 development claims its exact-label accuracy is 9 of 26 and it flags all 9 well-supported claims (false-alarm 9 of 9), below the generic Nemotron arms' exact accuracy. The Gate 0 rule says the gap against Constat and HealthIT.com stands, but no rival was a verdict-giving product and the Sakaime arm itself does not reach 0.80. Nothing here is independent: one builder wrote every key, no clinician has read any of it, and demand is unmeasured.
